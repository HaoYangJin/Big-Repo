# 验收与限制

## 本机环境

本次在 Windows、Python 3.14、Git 和已有 gh 登录环境中开发。工具要求 Python 3.11+，仅使用标准库；未安装全局依赖，未修改全局 Git 或插件配置。

## 已执行的检查

最终离线测试：48 项全部通过，失败 0、错误 0。六个技能通过 skill-creator 格式校验，所有新增 Python 文件通过 Python 3.11 语法解析；3.11 实际运行仍需远端矩阵验证。

标准库 trace 语句覆盖率：采集器 84.0%，仓库检查与展示工具 96.1%，报告生成器 97.5%。报告生成器测量包含真实资料重建；覆盖率不是分支覆盖，也不代表全部行为已验证。

研究资料包含 60 个档案、1,333 个已读文件、1,200 条提交、172 个 PR、160 个正式 GitHub Release、3,033 条关联工作流记录（未全局去重），接口错误 0；所有档案都保留逐来源抓取时间。

- 临时 Git 仓库测试：清洁与脏工作区、已暂存/未暂存互相抵消、指纹失效、越界与重命名、非祖先基准、分离 HEAD、缺少验证证据、首次失败后仍保留失败状态。
- 展示检查：公开/私有、默认不生成增长、Star History 明确选择、明暗主题 HTML、缺失素材、相对越界、引用式图片、URL 认证与查询参数脱敏、重复生成幂等、离线不发请求。
- 采集检查：公开/私有与不可访问样本、接口权限缺口、缓存时间、跨域跳转阻断、断点继续、原子档案写入、固定 60 个唯一仓库。
- 报告检查：候选信号带固定 URL 和行号，缺少发布不编造，档案固定包含六类玩法。
- 打包检查：两个平台清单一致、市场路径可解析、六个技能入口和独立参考资料、Markdown 本地链接。

开发期回归测试曾暴露引用式图片重复计数问题，已修正并保留回归用例。代码审查发现的 URL 回显和索引验证缺陷均已增加针对性测试；不能把开发过程中的失败记录写成从未发生。

## 真实平台验证状态

| 平台 | 结果 |
| --- | --- |
| Codex | 本机 CLI 可用；插件清单、市场路径和技能目录进行静态校验。未安装插件、未重启桌面客户端，实际加载和模型驱动任务未验证 |
| Claude Code | 本机未检测到 CLI；清单和目录进行静态校验，真实加载与典型任务未验证 |
| Linux / macOS | 配置了 GitHub Actions 三系统矩阵；本机没有执行这两个系统的测试，远端结果以 PR 检查为准 |

未验证的环境不计为通过。技能的行为场景目前通过工具集成测试与指令审查验证，不能宣称已做两平台真实代理端到端测试。

## 工具限制

验证证据由调用方声明，不是防篡改证明；指纹不覆盖忽略文件、子模块内容和外部环境。验收工具不会替调用方运行验证命令。
展示检查默认离线，不保证外部服务可用，不覆盖所有 Markdown 扩展、HTML 和页内锚点。所有返回链接的查询与片段脱敏；报告不保存命令的原始 stdout/stderr 或令牌。
PR 查询只是只读观察，不将未知或等待状态标为通过；项目政策、授权和 GitHub 权限仍需真实核对。

## 可复现命令

```text
python -m unittest discover -s tests
git diff --check
python scripts/build_research.py --data research/data --output research
```

覆盖率使用 Python 标准库 trace 测量语句覆盖，不等同于分支覆盖或测试充分性。全部测量不需要启动外部服务。

## 交付边界

最终提交交付可审查 PR 和插件 ZIP，不合并、不发布 Release、不打版本标签、不部署、不自动安装，也不向公共插件市场提交。研究快照与未知项详见研究方法和各档案。
