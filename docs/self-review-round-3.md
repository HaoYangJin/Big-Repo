# 第三轮自我优化：1.1.0

本轮在 1.0.0 合并提交 `3e720b960f8abe684bf274ae823010c47b87d315` 上实施。用户授权双平台支持、验收后自动合并、发布 1.1.0 并更新本机 Codex 插件；Claude Code 仅做云端加载和工具测试，不调用模型或安装本机客户端。

## 发现与修改

- 两份旧平台清单未提供新的便携入口：增加根 plugin.json，统一身份和市场版本，保留旧客户端入口。
- 技能中的相对脚本位置可能误指向目标仓库：增加实际插件根定位及带空格路径说明。
- 旧发行流程没有按当前提交持续验证两宿主：新增真实 ZIP 核验与两个隔离 CLI 作业，证据绑定 head 和 ZIP。
- 展示工具漏检可点击徽章目标、HTML 锚点和空白引用标签，也会把代码示例当正文：新增有界上下文扫描及回归用例。独立审查又发现注释与反引号交叉、HTML 属性中文字被误当代码的问题，均在正式验证前修正。

## 验证记录与边界

基线运行 72 项，70 项通过，2 项因 Windows 符号链接权限跳过。开发阶段在执行前声明的 TDD 红灯用于复现徽章与代码问题、便携清单漂移和新模块缺失；不把这些预期失败描述为从未发生。最终本地结果、三系统和双宿主结果以 PR 最终 SHA 的日志和发行附件为准。

本轮保留真实首页玩法，没有编造 Star、下载量或贡献者，也没有增加定时外部服务。展示检查仍为离线有界解析，不验证页内锚点、所有 Markdown 扩展和远端可用性。未做模型驱动任务，不将 1.0.0 的模型测试复用为本版本证据。完整验收方法见[双平台说明](host-validation.md)。

## 自动化规则续作

此前正式格式检查发现 docs/showcase.md 末尾空行，按旧协议交接，未删除失败记录。用户随后明确授权升级为自动修复和自动合并；本次修复该空行并接续已有改动，六份协议统一新规则，历史轮次说明保持原貌。连续三轮无可验证进展、必要权限缺失或工作区归属冲突时才交接，不因第一次失败中断。工具本身保持只读和现有合并门槛，不把加载验证扩大为模型任务。
