# 仓库玩法与持续展示

Big-Repo 2.0.0 将工具交互、真实展示和轻量挑战放在同一个离线入口中。Star History 只是增长展示的一项。

## 体验模块

- 能力地图：8 个技能、6 个模板和两个工具，按目标与类型组合筛选，查看前提并复制调用提示。
- 模板工作台：从同一能力目录读取模板，组合、预览、复制和下载草稿；提示项必须替换，草稿不是任务或证据。
- 交付沙盘：正常交付、测试失败、独立审查阻塞、CI 等待四种场景。
- 轻量挑战：后三种场景包含目标、提示和通关反馈；阻塞未解除不能推进，切换场景或重置清空当前状态。
- 版本足迹：CHANGELOG 与已核实 Release 快照；离线页面不查询最新发行，显示采集日期和候选状态。
- 展示方案：增长、状态、媒体、快速体验、社区参与、项目故事，按本地或公开条件筛选。

## 初始化与更新

create 和 init 在首次提交前或已有项目接入时补齐 README 托管展示与 docs/big-repo-explorer.html。后续客户端在最终提交前运行：

```sh
python scripts/repo_tools.py showcase-sync --repo /path/to/project --repository owner/project
# 仅在核实公开性后添加 --public
```

展示页使用固定演示，不提交不断变化的真实快照时间戳。重复执行不产生新差异；托管区外内容保留，已有非托管体验文件拒绝覆盖。真实项目结构报告仍需用 explore.py --repo 单独生成到新路径。

公开模式使用实际仓库和工作流名称生成图表与徽章，并保留 Star History 文字入口。公开性未知或私有时不嵌入第三方图片。状态图片不等于当前候选已通过验收；版本与 Star 数据也不代表质量、下载量或用户数。

## 维护与移除

能力与模板来自 assets/catalog.json 以及真实资源文件；版本来自 CHANGELOG 和已登记 Release 快照。新增技能、模板或正式发行后，维护相应目录和快照资料，不虚构数据。

删除 README 的 big-repo:showcase 托管区与 docs/big-repo-explorer.html 可移除生成展示。目录内入口更新时同步检查引用。离线页面无外部请求、不存储持久账号数据，挑战状态只存在于当前页面。

品牌社交图通过 ImageGen 生成，文件为 assets/social-preview.png；界面截图由实际浏览器生成，文件为 assets/explorer-demo.png，两者不可混称。
