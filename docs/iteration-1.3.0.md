# 1.3.0 目标对照与本仓库整理

## 分析依据

最初提交的 README 将目标定义为 Git 协作、提交说明、AI 技能规范及可复用模板。后续 1.0.0 插件扩展为六类技能与六类仓库玩法；1.1.0 增强验证和自动合并，1.2.0 引入一次接入与可恢复任务，但首页收缩后缺少实际可见、可操作的展示体验。依据为 Git 历史、插件 CHANGELOG、docs/showcase.md 的历史记录和现有脚本，并非不可见的会话记忆。

## 差距与本轮改进

| 目标 | 1.2.0 状态 / 差距 | 1.3.0 处理 |
| --- | --- | --- |
| 可复用规范和技能 | 六技能与独立参考完整 | 保留现有目录与协议，补充探索台使用边界 |
| 一次接入后完成交付 | 有任务、验证、审查和合并工具 | 保留实际门槛，修复 GitHub 仓库名大小写误判 |
| 可视化 | 首页展示已收起 | 恢复流程图、浏览器截图和结构信号 |
| 可玩性 | 主要为玩法目录和文字建议 | 实装四种交付演练、六类玩法筛选、快照导出 |
| 统一插件品牌 | 中文显示名与 repo-maintainer 制品 | Repo-Standards 显示名、ZIP 名和顶层目录；保留机器 ID 兼容性 |
| 易安装、易升级 | 源码目录与发行包路径需人工理解 | 分别说明源码、解压目录、既有项目升级和回退 |

## 按本版本规则整理本仓库

- 首页按“看流程 → 两分钟体验 → 首次接入 → 日常开发 → 参与”组织，研究不再成为上手前置条件。
- docs/showcase.md 从过时的“历史展示清单”改为当前可运行体验、维护成本、数据边界和移除方式。
- 双平台清单、市场版本、CHANGELOG、安装说明、构建及发布校验同步，旧版名称只用于历史兼容与回退。
- plugins/repo-maintainer 保持唯一运行源码；不复制插件、研究档案或自动生成的本仓库快照进源码目录。完整发行包包含运行所需 assets。
- 研究原始记录和三轮历史自审保留；本轮验收与独立审查单独记录，不改写历史结果。
- 继续复用项目配置中的完整测试、diff 检查、独立审查和三平台 CI；演练按钮永不生成真实交付证据。

## 完成边界

本轮准备 1.3.0 候选代码与本地制品，并按本仓库规则交付维护 PR。版本迭代不自动宣称 GitHub Release 已发布。正式标签、Release 与上传按明确发布指令执行。客户端真实加载、模型端到端行为与跨平台 CI 仅报告实际执行结果，详见[验收记录](validation.md)。
