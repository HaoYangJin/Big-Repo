# Big-Repo 2.1.0 发布说明

本文件为目标版本的发布材料，实际公开状态、日期与制品以 [Releases](https://github.com/HaoYangJin/Big-Repo/releases) 为准。

## 变化与动机

新项目接入现在先从本地提交、core 资源开始。客户端常驻说明、PR/合并以及仓库展示都需要显式选择；create/init 的 --dry-run 可预览变更。配置 schema 2 记录策略来源与时间，记录是协作声明，不能代替用户授权或平台权限。

upgrade 用暂存目录和备份更新运行资源；disconnect 只移除托管入口并停用接入，保留 README、运行目录、任务与 PR 历史。中断时先恢复，遇到用户新增文件或冲突拒绝覆盖。从 core 升到 full 必须使用完整插件源。

社区资料新增 MIT 许可证、行为准则和项目故事。详见 [变更记录](../CHANGELOG.md)。

## 升级与回退

先备份原配置、运行目录和任务状态。用原版完成或按用户指令取消活动任务；1.x 先执行命名空间迁移，再选择 2.1 策略。2.0 项目从完整新版插件执行 upgrade，明确 --delivery、--client、--profile；不从旧 merge 默认推断授权。完整命令见 [迁移说明](migration.md) 和 [安装说明](install.md)。

回退使用独立目录中的完整旧版及原配置备份，保留新旧日志。不得移动已有标签或覆盖已发行附件。需要撤回已公开发行时先评估下游影响并单独确认处置范围。

## 验证与边界

发布前要求最终提交通过 Python 回归、链接与元数据检查、独立 AI 审查及三平台 CI；合并后从固定提交运行测试、两次构建并比较字节，上传草稿附件后下载核验，再公开。实际结果见 [验收记录](validation.md)、对应 PR 和发行工作流。

本轮不把客户端模型端到端、安装或部署记为通过，不修改全局客户端设置。离线演练不执行真实交付，也不是验证证据。
