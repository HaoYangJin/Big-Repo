# 自动修复交付场景

自动修复由加载技能的 AI 执行，检查脚本只读返回结果；没有新增后台代理或无限重试程序。以下场景用于审查技能行为，不能把规则文本检查称为模型实测。

| 输入情况 | AI 应执行的操作 | 必须保留的证据与停止条件 |
| --- | --- | --- |
| 本次 README 多一个末尾空行，diff --check 失败 | 记录失败，移除该空行，重跑格式检查并继续完整验证 | 原失败记录保留；本次续作实际覆盖此场景 |
| 本次代码导致测试或 CI 失败 | 定位失败、在范围内修复，运行相关测试与最终全量验证，更新 PR | 新 head 重新检查与审查；旧证据不能合并 |
| 同一错误连续三轮没有复验确认改善或新证据定位根因 | 第三轮结束后保留现场，一次性交接，不继续无效循环 | 三轮命令、退出码、修改、复验及无进展判定 |
| 一轮找到新根因、后续复验确认部分失败消失 | 清零连续无进展计数，继续剩余问题 | 仅改文件或换解释不算进展 |
| 网络短暂失败 | 最多三次尝试，重试前依次等待 5 秒和 15 秒 | 非幂等操作先查询远端是否已经完成 |
| 缺少写入权限或工作区有归属不明的冲突 | 保留现场并交接，不改凭据、不覆盖他人工作 | 权限或冲突证据；不使用 --admin |

工具回归测试覆盖：失败不能验收、失败与成功混在最终集合中不能掩盖失败、历史单独归档后新证据可通过、修改或提交使旧证据失效、CI 失败阻断合并、修复新提交须新审查和成功 CI、权限不足仍不能合并。六份协议一致性与上述三轮行为由独立指令审查确认；本轮未调用模型，不宣称三轮决策已经完成模型端到端测试。
