# 变更记录

## 1.1.0

- 维护默认改为范围内自动诊断修复、重新验证、独立 AI 审查及复审，CI 成功后自动合并；外部权限、网络或范围外决策才交接。
- 新增 `repo_tools.py merge`：重新运行全部合并门槛，锁定最终 head SHA 执行一次 squash 合并，查询远端 MERGED 与合并提交后才返回成功；等待、失败、队列与不确定写入均不误报完成。
- 统一六项技能的任务协议、研究建议说明、任务和交接模板，明确历史失败日志与当前候选证据的区别。
- 指定版本发布可复用同一委托中的明确授权；默认仍只准备材料，不部署、不配置常驻自动化或全局插件。
- 更新双平台插件清单、市场版本、下载与升级入口，补充合并工具的隔离回归验证。

兼容旧的任务与证据格式，新增合并命令会写远端。行为迁移：旧版首次失败停止改为自动修复；需要旧策略的任务可明确声明首次失败交接。历史客户端加载证据不代表本版已完成加载或模型端到端验证。

## 1.0.0

首次 GitHub 发行的版本内容，整合此前未发布到 Releases 的 0.1.0 与 0.2.0 源码成果。

- 六项共享技能：仓库接管、维护交付、仓库审查、发布准备、技能维护与仓库展示。
- 基于 60 个官方或组织仓库的分类研究，插件内置精简结论与可追溯来源，完整档案保留在源仓库。
- 只读预检、验收、合并门槛及展示检查；验证、独立审查与 CI 全部通过后默认自动合并，首次非预期失败交接。
- 六类固定仓库玩法，支持按项目筛选；私有仓库不向公开图表服务发送标识，不编造趋势。
- 修复打包临时文件名冲突、中断残留及校验和输出跟随符号链接；保留确定性 ZIP 与 SHA-256。
- 增加版本化下载入口和安装、校验、升级及回退说明。

与 0.2.0 的技能调用及工具命令兼容，无任务模板迁移要求。Python 工具要求 Python 3.11+、Git；GitHub 查询与采集还需已登录的 gh。未引入常驻服务、全局自动安装或部署。

Codex 已完成隔离安装、六技能发现，并在用户另行授权本机安装后用真实模型执行 repo-showcase 离线审查；Claude Code 已完成清单校验、实际加载和六技能清点，模型任务尚未验证。没有将这一冒烟场景扩大为六技能全部端到端通过。正式发布仅在用户明确授权的独立发布任务内执行；技能默认仍只准备发布材料。
