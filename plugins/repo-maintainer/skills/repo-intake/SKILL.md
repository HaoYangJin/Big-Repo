# 仓库接管

先阅读 [任务协议](references/task-protocol.md)。

核实仓库与远端、分支、工作区及任务目标；基准固定为完整提交 SHA。按 SDK、代理技能、模型、应用框架、基础设施、开发工具选择相应检查重点，允许混合类型。
列出真正适用的项目规则、生成文件边界、测试入口、发布方式和外部依赖。不能因为没有 GitHub Actions 就认定没有 CI。
检查是否为镜像或要求邮件、Gerrit 等贡献渠道；GitHub PR 不适用时按项目规则交接渠道选择，不创建无效 PR。
展示与玩法是固定检查维度：查看 README、徽章、图表、媒体、演示、贡献入口与版本故事。标注已有内容、缺失内容和本任务可能影响的项目；维护任务不自动加入装饰。
确认公开性前按私有仓库处理，不将仓库标识发给公开统计服务。
交付任务记录、验证清单、既有工作处理结果和下一步；基线失败按协议诊断并在范围内修复；必要权限缺失时完成未受阻工作后交接。

选择实现或评审标准时，按需阅读 [研究案例](references/cases.md)，区分来源事实与本插件建议。
