# 仓库接管

先阅读 [任务协议](references/task-protocol.md)。

用户明确要求“为本项目启用自动维护与交付”时，按 [接入步骤](references/project-workflow.md) 检查项目、推断验证命令与交付规则，再运行 project_workflow.py init。默认保存项目级 AGENTS.md / CLAUDE.md 入口与可复用运行文件；保留已有说明和用户工作，不修改全局客户端设置。必要认证复用客户端已有连接，不保存凭据值。
配置一次后，普通开发需求和反馈由 maintenance-delivery 处理；无需每轮重新接入。CI 检查名称从实际平台结果和项目规则确认，不能只因本地没有工作流文件就推断无 CI。初始化的 needs-configuration 项由当前 AI 继续调查和补齐，只有凭据或真正缺失的用户决策才交接。

核实仓库与远端、分支、工作区及任务目标；基准固定为完整提交 SHA。按 SDK、代理技能、模型、应用框架、基础设施、开发工具选择相应检查重点，允许混合类型。
列出真正适用的项目规则、生成文件边界、测试入口、发布方式和外部依赖。不能因为没有 GitHub Actions 就认定没有 CI。
检查是否为镜像或要求邮件、Gerrit 等贡献渠道；GitHub PR 不适用时按项目规则交接渠道选择，不创建无效 PR。
仅在用户要求展示维护或本轮改动影响相应内容时检查 README 素材、徽章、图表和演示，不把普通开发需求扩成展示或全仓治理任务。
确认公开性前按私有仓库处理，不将仓库标识发给公开统计服务。
交付任务记录、验证清单、既有工作处理结果和下一步；基线失败按协议诊断并在范围内修复；必要权限缺失时完成未受阻工作后交接。

选择实现或评审标准时，按需阅读 [研究案例](references/cases.md)，区分来源事实与本插件建议。
