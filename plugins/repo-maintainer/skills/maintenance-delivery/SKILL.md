# 日常维护与自动合并交付

执行前阅读 [任务协议](references/task-protocol.md)，复用已有接管结果。目标不够明确时先确定完成条件，不自选无关功能。

- 缺陷修复：用可复现输入确认问题，按项目测试习惯验证行为；不要只修改断言迎合实现。
- 依赖升级：核对版本约束、官方变更说明、锁文件、兼容范围和安装方式；生成文件用项目支持的工具更新。
- 文档同步：核对描述与实际命令、配置和版本，检查链接及展示示例。
- SDK 生成代码：先找生成源与手写扩展边界，避免直接修补会被生成器覆盖的文件。
- 单仓多包和基础设施：确认受影响组件与相关测试，不默认全量流程或跳过必要测试。

修改前识别本次任务影响的 README 截图、徽章、图表和快速体验入口，只同步有关内容。
完成必要基线检查后修改并验证。失败时按任务协议自动诊断、修复与复验，连续三轮无可验证进展或确需补充权限时才交接。
验证通过后核对差异与暂存范围，按授权提交、推送任务分支、创建 PR。完成独立审查，等待登记的 CI 与其他可见检查全部成功，运行 merge-readiness 并锁定 head SHA 后自动 squash 合并；不绕过平台规则、不删分支。CI 或审查失败则自动修复、更新 PR 并重新验收，不把创建 PR 等同于成功交付。
提交署名、签署和 AI 使用披露按项目实际规则处理，不伪造作者身份或人工审查记录。

选择实现或评审标准时，按需阅读 [研究案例](references/cases.md)，区分来源事实与本插件建议。

## 工具位置

完整插件的共享工具位于插件根目录的 `scripts/repo_tools.py`，目标仓库不是插件目录。Claude Code 加载本入口时，插件根路径为 `${CLAUDE_PLUGIN_ROOT}`；其他宿主从实际加载的本 SKILL.md 所在技能目录上溯两级定位插件根，不把未展开的变量当作路径。先确认工具文件存在，再以带引号的绝对路径运行，并用 `--repo` 显式指定目标仓库；不要在目标仓库中寻找同名脚本。只复制技能目录、没有完整工具时，按任务协议手工核对并说明未自动验证的部分。
